# 陇碳智策 · 设备节能与碳减排评估平台

当前版本 **8.2.12**（Vue + FastAPI）。帮助矿山企业把设备能省多少电、相应少排多少碳、投资多久能收回，按有据可查的数据算清楚。

金徽公开案例为只读示范；上传企业数据会生成会话专属项目，**不会隐式继承**金徽 200kW / 100 万元投资 / 电价假设。

本平台**不是**官方企业碳核证或正式节能量核证系统。主功能是设备级节电、相应电力相关排放变化，以及有条件的投资经济性情景估算。

## 金徽基线（须守住）

- 200 kW × 4,000 h ＝ 800,000 kWh
- 采用注明年份的 0.4471 kgCO₂/kWh → 357.68 tCO₂
- 改为 2,000 h 后为 400,000 kWh、178.84 tCO₂

## 一键启动（Windows）

双击 `一键启动.bat`，在本机启动服务，浏览器打开 http://127.0.0.1:8000

脚本会使用或创建 `backend/.venv`，安装依赖，并由 uvicorn 同时托管 API 与已构建的 `frontend/dist`。请保持弹出的命令行窗口开着。脚本会核对 /api/health 的版本号是否为 8.2.12，避免误开旧进程。

若页面异常：先关掉占用 8000 端口的旧窗口，再重新双击，浏览器使用 Ctrl+F5。

双击 `一键打开公网.bat`，用系统默认浏览器打开当前公网演示：
https://longtan-zhice-73b61.containers.snapdeploy.app

这只会打开公网页，不会在本机启动服务，也不会读写本机企业数据库。免费实例空闲约 15 分钟后可能休眠，第一次打开可能需要约 60–90 秒唤醒。公网演示数据与本机项目不是同一份。

## 数据保存说明（比赛演示优先本机）

- **推荐**：在 Windows 上双击 `一键启动.bat` 做离线稳定演示。企业项目保存在本机 `backend/data/projects.sqlite`，重启后仍在。
- 请同时通过报告页导出 TXT / CSV / HTML，并保存截图，避免只有在线单份。
- **免费云实例**（Render Free、SnapDeploy Free 等）空闲约 15 分钟可能休眠；唤醒可能需要约 60–90 秒，且可能拉起新容器。同一容器短暂暂停后数据可能还在，但不能保证休眠/唤醒、重启或重新部署后仍然保留。不要把免费在线实例当成企业数据的长期存储，也不要承诺试用者数据会被持续保存。本版本**没有**实现云端持久化数据库，只把这一限制写清楚。公开示范写在应用代码中，唤醒后可通过「恢复公开案例」重新载入；**不要**把私有企业数据提交到公开代码仓库。
- 若必须在线长期保存，需要自行改用外部托管数据库或挂载持久卷，并完成备份与权限验收。本仓库默认配置没有做这项迁移。
- `/api/health` 的 `data_persistence` / `data_persistence_note` 字段会再次说明上述边界。




## 身份与权限（V8.2.12）

- **工作区会话**：浏览器持有成对的 `ltzs_sid` + 带时间戳的 HMAC Cookie `ltzs_stk`。验证通过后，可恢复该所有者名下的全部企业项目。服务端会检查签发时间、过期和撤销；浏览器 Cookie 的 7 天有效期不能代替这项校验。页面提供「退出当前工作区」，对应 `POST /api/session/logout`。8.2.7 无签发时间的旧格式 Cookie 不再被接受。
- **访客不等于所有者**：有签名 Cookie 只证明当前浏览器会话可信，并不等于拥有正在访问的项目。必须按项目核对服务器记录的 `owner_session` 是否等于当前可信 Cookie 会话。
- **项目 Token**（`X-Project-Token`）：只对应一个项目，可用于访问该项目，不能自动授权同一所有者的其他（兄弟）项目，也不得把访客提升为所有者。访客授权与真正所有权分开存储。退出工作区**不会**自动作废已发放的项目凭证；需要作废时请由**原所有者**使用「轮换项目凭证」或「撤销项目凭证」（`POST /api/session/project-token/rotate` / `revoke`）。访客调用这两项接口会返回 403，且不会改动原 Token。
- **轮换/撤销会失效访客授权**：所有者轮换或撤销后，所有从旧 Token 衍生的授权、缓存的项目 ID、活动项目、项目 Token 以及已签发访客 Cookie 上对应的项目权限一并失效。旧访客不会在响应正文或 `X-Project-Token` 头中收到新 Token。
- **恢复版本不改所有权**：恢复已存在项目的历史版本时，严格保留服务器记录的原始所有权；仅原所有者可以恢复（访客得到 403）。快照里的旧 Token、`owner_session`、revision 不会覆盖服务器当前的有效权限状态。
- **未签名的历史 `X-Session-Id`**：服务器重启后，仅重放会话号不会重新签发信任凭证，也不能接管历史身份。
- **改变状态的请求**会校验 `Origin`（或 `Referer`）：只接受 CORS 白名单、`LTZS_PUBLIC_ORIGIN`，或与当前请求 scheme+host+port 完全同源的来源。若 Origin 的主机名已出现在这些配置来源中，但 scheme+host+port 并未精确命中，则直接拒绝，不再回退到容器看到的请求协议（避免 TLS 终止后把 `http://` 同一公网主机误判为同源）。不要用客户端可伪造的 `X-Forwarded-Proto` 判断 CSRF。无 Origin 的 pytest / 本地脚本按非浏览器 API 客户端兼容；跨站或跨协议同主机 POST 会被拒绝。8.2.9 已改为比较完整 scheme+host+port；8.2.10 补上反代 HTTP 场景下的主机名锁定（本版保留）。
- **健康检查** `GET /api/health` 不会创建会话或票据。公网 HTTPS 请设置 `LTZS_COOKIE_SECURE=1`。

## 手动启动

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

前端构建（修改页面后必须重新构建，后端才看得到最新表单）：

```bash
cd frontend
npm ci
npm run build   # 产物写入 frontend/dist，由后端静态托管
```

健康检查：`GET /api/health` 应返回 `ok: true` 且 `version` 为 `8.2.12`，与页面页眉版本一致。

## 支持范围与限制

- 已有 11 种细分设备类型与通用/专业方法；本版不新增设备下拉选项
- 报告导出支持 **TXT / CSV / HTML**。未提供原生 PDF 引擎：请求 `format=pdf` 会诚实返回不支持
- 缺少电价、投资或运维时，节电和减碳仍可展示，但不会给出确定回本或“经济最优”
- 矿井主扇的安全最低风量必须大于 0 并经过核对，才允许实施/经济推荐
- 专业模型会返回改造前电输入功率 `before_input_power_kw`，并与设备登记功率核对；轴功率不等于输入功率
- 国家标准链接是方法与合规依据，不是这台设备的实测效率
- 报告会区分三类数据：企业实测/企业填报、公开资料可复核摘录、用户试算假设。没有型号效率的采购公告或电网因子公告不能冒充设备效率出处
- 历史候选报价只能作价格敏感性参考，不会自动变成完整改造投资
- 演示数据与正式企业数据按会话隔离；自动测试通过不等于完成生产级渗透测试

## 安全上线前提（尚未声称已全部具备）

正式托管企业敏感数据前，还需独立落实 HTTPS、权限、留存、删除和备份要求，并与演示数据隔离。
